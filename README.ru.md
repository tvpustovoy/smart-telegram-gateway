# smart-telegram-gateway

Умный и надёжный шлюз между Telegram и ИИ-агентом, который работает сессией Claude Code: ничего не теряется, и агент не
тратит ходы на рутину, которую шлюз делает сам.

[English version](README.md) · [Изменения (англ.)](CHANGELOG.md) · [Issues][issues]

## Что это и зачем

Говорить с личным агентом через бота Telegram просто, пока сессия агента не занята, не сжимает контекст, не
перезапускается и компьютер не спит. Иначе сообщения теряются, получают ответ дважды или остаются без знака, видел ли их
агент вообще.

smart-telegram-gateway — небольшая служба, которая держит бота и стоит между Telegram и агентом:

- **Агент делает только то, что требует его.** Квитанции, закреплённая строка состояния, расшифровка голоса, команды,
  учёт эпизодов, окно отмены реакций, доставка новых правил агенту — всё это шлюз
  делает сам, детерминированно. Ходы и токены агента уходят только на то, что требует думать.
- **Ничего не теряется.** Каждое сообщение записывается в локальную базу SQLite до того, как Telegram узнаёт, что оно
  получено. Агент не на связи — сообщения ждут и приходят по порядку, когда он вернётся. Доставка агенту — «как минимум
  один раз», с повтором, если агент молчит.
- **Видно, что происходит.** Реакция на сообщении живёт, пока ждёшь ответа: 👀 — агент увидел; ответ агента её
  снимает (знак ответа — сам ответ); 👌 — агент закрыл сообщение без ответа, снимется следующим твоим сообщением
  (`ui.clear_receipts`; 👌 прежних версий на отвеченных сообщениях остаются как были). Закреплённая строка показывает
  тему и состояние агента: на связи, думает или нет, сколько занято контекста, лимиты, отказ модели.
- **Слово владельца отделено от материала.** У каждого события — метка доверия: собственные слова владельца или
  пересланное, чужое, текст на картинке. Агенту сказано, что материал — не указание. Пересылка, ссылка без слов
  (страница, которой поделились из браузера), файл или фото без слов владельца недолго ждут его слов и приходят агенту
  вместе с ними (`ui.material_hold_seconds`); ссылка реплаем на сообщение агента — ответ ему и уходит сразу; реплай на
  материал и первые слова после него (`ui.material_followup_minutes`) агент видит как слова к этому материалу.
- **Доступ держит шлюз.** Кто и в какой роли говорит с агентом, решает шлюз по `rules.yaml`. Агент может сузить доступ
  сразу, расширить — только после кнопки владельца.
- **Голос.** Голосовые, кружки и аудиофайлы распознаются (OpenAI или ElevenLabs), расшифровка приходит цитатой ответом
  на сообщение. Агент может ответить голосом.
- **Эпизоды.** Сообщения складываются в эпизоды (тема × роль), которые закрываются после паузы; в любой момент — стоп,
  пауза, новая тема, «где мы».
- **Картинки и файлы.** Агент смотрит фото и скриншоты по запросу и присылает документы из папки посылок.

Агент подключается переходником. Сейчас это `stg-channel` — MCP-сервер, который Claude Code загружает каналом (Claude
Code Channels) и который доносит события в работающую сессию. Протокол шлюз ⇄ переходник не привязан к Claude Code:
другие агентные среды можно добавить переходниками позже.

## Требования

- **macOS** — служба пользователя (LaunchAgent), секреты — в связке ключей.
- **Node.js ≥ 22.13** — встроенный `node:sqlite`.
- **Claude Code с каналами** (research preview): сессия агента запускается с
  `--dangerously-load-development-channels server:smart-telegram-gateway` и при каждом старте просит подтверждения —
  её запускает человек в окне терминала или в `tmux`.
- **Бот Telegram** и его токен от [@BotFather](https://t.me/BotFather).
- **Для голоса (по желанию):** ключ OpenAI (по умолчанию) или ElevenLabs.

## Установка

```sh
git clone <этот репозиторий> smart-telegram-gateway
cd smart-telegram-gateway
scripts/install-macos.sh <имя_бота> [--node <путь>] [--agent-dir <папка>] [--timezone <пояс>]
```

Значения по умолчанию — `scripts/install-macos.sh --help`. Скрипт собирает репозиторий, заводит каталог бота
`~/.smart-telegram-gateway/<бот>/` с `config.yaml`, ставит и запускает службу, разворачивает папку агента из шаблона
`scripts/agent-folder/` и печатает, что делать дальше. Повторный запуск переустанавливает службу, не трогая настройки,
правила, базу и заметки агента; `scripts/uninstall-macos.sh <бот>` убирает службу.

`stg` ниже — CLI шлюза: `alias stg="node --disable-warning=ExperimentalWarning $PWD/packages/cli/dist/index.js"`.

1. Токен бота — в связку ключей (команда спросит его без эха):
   `security add-generic-password -s smart-telegram-gateway -a <бот>/telegram -w`
2. Ключ голоса (по желанию): `security add-generic-password -s smart-telegram-gateway -a openai -w`
3. Владелец: пока `owner_id` в `config.yaml` пуст, шлюз в режиме первой настройки и никого не слушает. Напишите боту
   `/start`, `stg doctor` покажет ваш номер Telegram — впишите его в `owner_id` и перезапустите службу командой
   `launchctl kickstart -k …`, которую напечатал скрипт установки.
4. Сессия агента: `<папка агента>/start.sh` в отдельном окне терминала или в `tmux`; подтвердить канал разработчика, в
   первый раз — `/login`.
5. `stg doctor` — все проверки должны пройти; `stg status` и `stg where` показывают, что делает шлюз.

Агент работает под тем же пользователем macOS и может читать его файлы, в том числе файлы шлюза: это не песочница
(`docs/THREAT-MODEL.md`). Подробно о папке агента — [scripts/agent-folder/README.md](scripts/agent-folder/README.md).

## Настройки

`~/.smart-telegram-gateway/<бот>/config.yaml`, после правки — перезапуск службы; лишний ключ — ошибка. Главное:

```yaml
bot: my_assistant_bot
owner_id: 123456789              # номер владельца в Telegram; пусто — первая настройка
timezone: Europe/Berlin
stt: { provider: openai, model: gpt-4o-mini-transcribe, key: openai, language: ru, vocabulary: [Acme, Kubernetes] }
tts: { provider: openai, model: gpt-4o-mini-tts, voice: alloy }
parcels: { dir: null, targets: [telegram] }   # null — parcels/ в рабочем каталоге сессии агента
reactions: { hold_seconds: 3 }                # окно отмены реакции; 0 — сразу; не больше 3
# окно для материала без слов, с (0 — сразу; ≤ 600); «слова после материала», мин (0 — нет; ≤ 120);
# ответ снимает 👀, следующее сообщение — 👌 (false — 👌 остаётся, как до 0.3.6)
ui: { material_hold_seconds: 60, material_followup_minutes: 10, clear_receipts: true }
```

Распознавание и синтез можно взять у разных провайдеров (`openai` — в том числе OpenRouter, только распознавание;
`elevenlabs`). Ключи — только в связке ключей, в адресе их быть не должно. Правила доступа — `rules.yaml` рядом:
участники и чаты с ролью; ручная правка читается при перезапуске, `stg rules show` показывает действующие правила.
Полный перечень настроек — [docs/TECH-SPEC.md](docs/TECH-SPEC.md), раздел 5.1. Английский README подробнее.

## Сборка и тесты

```sh
npm ci
npm test         # tsc -b и все модульные и интеграционные тесты (node:test) на подделках
```

Около 700 тестов, примерно две минуты. Под тестом (`STG_TEST=1`) шлюз не ходит ни в настоящий Telegram, ни к
провайдерам голоса, не трогает связку ключей и launchd; временные каталоги удаляются (оставить — `STG_TEST_KEEP=1`).

Перед выпуском — проверка на то, что нельзя публиковать: `STG_DENYLIST=<файл> npm run release-check` (с `-- --history` —
и вся история). Закрытый список запретного лежит вне репозитория; подробно — раздел «Release check» в
[README.md](README.md#release-check).
