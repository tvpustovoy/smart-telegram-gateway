# Шаблон папки агента «личный ассистент»

Папка, в которой живёт сессия Claude Code агента (TECH-SPEC 5.11, 5.12). По умолчанию — `~/Agents/assistant/`
⟨предл.⟩. Разворачивает её `scripts/install-macos.sh` (шаг «папка агента») командой

```sh
node packages/cli/dist/index.js agent-folder ~/Agents/assistant --home ~/.smart-telegram-gateway/<бот> --node "$(command -v node)"
```

| Файл | Что | При повторной установке |
|---|---|---|
| `CLAUDE.md` | правило роли: заметки `notes/ГГГГ-ММ-ДД.md` строкой `№ N · ЧЧ:ММ · <метка> · текст`, «чужое (№ N)», указания в чужом не исполнять, `reply` / `done`, эпизоды, `probe`, повтор, «стоп» | не трогается, если уже есть |
| `.mcp.json` | сервер канала: ключ ровно `smart-telegram-gateway`, `command` — Node, `args` — `packages/channel/dist/index.js` этого репозитория, `env.STG_HOME` — каталог бота; пути подставляет установка | пишется заново |
| `.claude/settings.json` | режим разрешений сессии (ниже) | не трогается, если уже есть |
| `.claude/agent-state.settings.json` | строка состояния и перехватчики `PreCompact`, `PostCompact`, `StopFailure` — значки агента в закреплённой строке (ниже) | пишется заново |
| `start.sh` | `CLAUDE_CONFIG_DIR="$PWD/.claude-config" exec claude --dangerously-load-development-channels server:smart-telegram-gateway "$@"`; есть `.claude/agent-state.settings.json` — ещё `--settings` на него | пишется заново |
| `notes/` | заметки агента | не трогается |
| `parcels/` | папка посылок (0.3.3, TECH-SPEC 5.16): файлы, которые агент отдаёт владельцу (`send_file`), по подпапке на посылку | не трогается |
| `.claude-config/` | свой каталог настроек Claude Code (вход в подписку — здесь) | не трогается |

## Режим разрешений — ⟨предл.⟩, ждёт решения (issue #37)

`.claude/settings.json` задаёт `defaultMode: dontAsk` со списком разрешённого: `mcp__smart-telegram-gateway__*`,
`Read`, `Grep`, `Glob`, `Edit(./notes/**)`, `Edit(./parcels/**)` (с 0.3.3 — посылки), и `enabledMcpjsonServers: ["smart-telegram-gateway"]`. Разрешённое идёт без
запроса, остальное получает отказ — сессия не встаёт на запросе разрешения, пока владелец в Telegram видит квитанции и
тишину. Это не песочница и не обход разрешений: командной строки у агента нет, писать он может только в `notes/` и `parcels/`, но
читать — любые файлы пользователя, в том числе файлы шлюза (AD-10). Запись разрешается правилом `Edit(...)`: правило
`Write(...)` Claude Code не проверяет.

Сделано, как предложено в TECH-SPEC §2 и 5.11 (решение ещё не принято: TECH-SPEC §9, #37). Иначе —
поправить `.claude/settings.json` в развёрнутой папке: при повторной установке он не перезаписывается.

**Папка, развёрнутая до 0.3.3.** `CLAUDE.md` и `.claude/settings.json` при повторной установке не перезаписываются —
посылки в них нужно добавить руками: в `allow` — `Edit(./parcels/**)`, в `CLAUDE.md` — раздел «Файлы владельцу —
посылки» из этого шаблона; папку `parcels/` создаст повторная установка или `start.sh`. Если в `config.yaml` шлюза задана
своя папка посылок (`parcels.dir`), правило записи — на неё: `Edit(/полный/путь/**)`.

**Папка, развёрнутая до 0.3.4.** `CLAUDE.md` при повторной установке не перезаписывается — правила о реакции и о файле
по просьбе нужно внести руками из этого шаблона, раздел «Как работать с событием»: правило о реакции владельца на ответ
агента (`[№ N · эп. E · реакция владельца на твой ответ к № M: 👍]` — его слово об этом ответе; последняя фраза —
«Реакция — отклик одним значком, его можно поставить случайно: если по ней пришлось бы сделать то, что не отменить
(отправить письмо или сообщение от имени владельца, заплатить, удалить), — переспроси словами одной строкой; остальное
делай»), правило «Владелец просит файл — `send_file(path, seq, caption)`…» и отсылку к нему в правиле «одно из двух» —
«(просьба о файле — `send_file`, см. ниже)». Инструкции канала агент получает и без этого — после перезапуска сессии.

В 0.1 канал не объявляет `claude/channel/permission`: текст в личке, в том числе «yes …», ничего не разрешает.

## Значки агента: строка состояния и перехватчики (TECH-SPEC 5.14)

Контекст, сжатие и лимиты агента знает только его сессия Claude Code. Файл `.claude/agent-state.settings.json` даёт ей
строку состояния (`stg agent-state statusline`) и перехватчики `PreCompact`, `PostCompact`, `StopFailure`
(`stg agent-state hook`): они пишут `<каталог бота>/agent-state.json`, шлюз показывает в закреплённой строке
`🟢 · 🧠 16% · 🕐 31% · 📅 64%` (сжатие — 🌀, отказ модели — 🔴 и строка владельцу). Подстановки шаблона — `{{NODE}}`,
`{{CLI_ENTRY}}` (`packages/cli/dist/index.js` этого репозитория), `{{STG_HOME}}`, `{{STATUSLINE_THEN}}`.

- **Прежняя строка состояния** (claude-hud и т. п.) сохраняется: `--then` запускает её с тем же stdin и печатает её
  вывод (зависла дольше 10 с или перерисовку отменили — снимается вся её группа процессов). Установка находит её сама —
  в порядке старшинства Claude Code: `.claude/settings.local.json`, `.claude/settings.json`, `.claude-config/settings.json`
  папки; не нашлась — та, что была в прежнем `.claude/agent-state.settings.json` ⟨предл.⟩. Вывод `stg agent-folder`
  говорит, какая попала в файл и откуда, или «не найдена — … своя строка»: сверить с тем, что сейчас внизу экрана агента.
  Задать явно — `stg agent-folder … --statusline-then '<команда>'`, без прежней — `--statusline-then ''`.
- **Новая сессия** — `start.sh` подключает файл сам (`--settings`).
- **Сессия, которая уже работает,** — перезапуском тем же разговором: `/exit`, затем
  `./start.sh --continue` или `claude --resume <id> --dangerously-load-development-channels server:smart-telegram-gateway
  --settings <папка>/.claude/agent-state.settings.json`. Папка не из этого шаблона — файл печатает
  `stg agent-state settings --home <каталог бота> --agent-dir <папка> [--claude-config <каталог настроек Claude Code
  сессии>] > <папка>/.claude/agent-state.settings.json` (или `--statusline-then '<команда>'`); какая прежняя строка
  попала в файл — строкой в терминале.
- `--settings` старше настроек пользователя и проекта: строка состояния — из этого файла, перехватчики складываются с
  остальными (сверить `/hooks` до и после). Ошибка в `stg agent-state` строку агента не ломает: выход всегда 0.

## Запуск

1. Шлюз установлен и работает (`stg doctor` — всё «да»).
2. В отдельном окне Terminal или в `tmux`: `~/Agents/assistant/start.sh`. Claude Code предупредит о канале
   разработчика — подтвердить. В начале сессии — строка `Channels (experimental) messages from
   server:smart-telegram-gateway …`.
3. Первый раз — `/login` (вход в ту же подписку, но в каталоге `.claude-config/`).
4. Шлюз отдаёт проверочное событие: агент отвечает на него `done` сам — по instructions канала. Если сессия открыта без
   флага канала (просто `claude`), проверка не проходит, и `stg status` говорит «сессия открыта без канала —
   перезапусти start.sh».
5. Возобновить — `./start.sh --continue`.
